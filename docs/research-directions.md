# 原创方向规划（Research Directions）

> 本文档记录 AI-PoisonGuard 从「工程完整」走向「有原创贡献」的可行路径。
> 当前定位：组合 + 诚实验证型工作（Level 1）；本页列出把项目升级为 Level 2/3 的具体动作。

## 现状定位（诚实基线）

四层防御（M1 权重初筛 → BAIT + 多 token 搜索 → 差分探针 → 校准融合）在方法上均为已有技术，
我们的贡献在于**把它们组装进一个没人组装过的完整供应链检测场景，并做了一套可复现的验证方法学**。

已有两个「原创种子」——实测发现，但尚未被当作原创成文：

1. **行为检测器对干净模型也高置信**：clean_s42 上 multi-token 搜索 best_confidence=0.948，
   而该模型无后门。现有工作几乎只报「对投毒模型检出率」，很少测「对干净微调模型误报率」。
   由此提出三通道证据合议规则（m1≥0.9 且 bait≥0.8 且 multi_token≥0.9 才 block），实测 0 误报。
   - 证据：`Demo/backend/data/firewall_reports/20261004_150529_clean_s42.json`
   - 成文雏形：发现现象 → 提出规则 → 验证 0 误报

2. **差分探针的结构性失效**：干净标签模板使未微调基座 flip_base=1.0，差分相消导致
   conjunction delta=-0.8、cleanlabel delta=-0.88，探针通道对 badnet_mn 贡献≈0。
   证明「微调−基座翻转率差分」这族方法在「基座本身对某类探针高翻转」时会失效。
   - 证据：`Demo/backend/data/firewall_reports/20261004_142421_badnet_mn.json` 的 probes 通道
   - 成文雏形：证明流行方法在何种条件下失效（学术界接受「反面发现」）

## 方向一（最推荐）：自适应攻击评估

**动机**：现有评估假设攻击者不知道防御。真实场景中攻击者会专门针对防御绕开。
「防御在知情攻击者面前是否成立」是当前 LLM 供应链安全最缺的数据。

**怎么做**：
1. 以四层防御为靶子，训练「避开探针」的后门——例如用非 `cf/mn/mb/bb/tq` 词表内的触发词，
   或避免 clean-label 模板前缀，观察哪一层首先失守
2. 逐层做消融：关掉某一层，攻击成功率(ASR)上升多少 → 量化每层对「知情攻击」的真实边际贡献
3. 产出：一张「防御层 vs 攻击策略」的对抗矩阵

**预期产出**：一篇 workshop/短文的实验主体；简历可写「在 adaptive adversary 设定下
评估四层防御，发现 X 层可被 Y 绕过，据此提出 Z」。

**工作量**：2–3 周（训练适配器 + 跑检测 + 消融）。**风险**：低，几乎必有可写的发现（哪怕发现防不住）。

## 方向二：跨模型 / 跨分布迁移性

**动机**：全部结论建立在 GPT-2 124M + SST-2 上。「结论能否泛化」是审稿人必问。

**怎么做**：
1. 换基座：用另一家族小模型（如 GPT-Neo-125M / DistilGPT2）重复 benchmark_v2 的投毒训练
2. 换分布：把后门注入换到非情感分类任务，观察行为层/探针层是否依然有效
3. 产出：一条「结论稳健性」曲线，标注哪些层是 base-agnostic、哪些层依赖具体 base

**预期产出**：补上「泛化性」这一最容易被挑战的缺口。**工作量**：1–2 周/个设定。

## 方向三：干净模型误报基线基准

**动机**：方向一种子 #1 只是单点（一个 clean_s42）。把它系统化，就能定义一个
「行为检测器误报基线」，别人的方法都得拿它对比。

**怎么做**：
1. 用已有的 60 个 V1 干净适配器（`Demo/backend/data/lora_benchmark/clean/`）批量跑
   BAIT + multi-token，收集每个模型的置信度分布
2. 统计：误报率分布、最高误报置信度、哪些干净模型最容易被误判
3. 产出：`false_positive_baseline.json` + 一篇「行为后门检测器误报率基准」报告

**预期产出**：一个可引用的基准（定义「误报基线」这件事本身是贡献）。**工作量**：几天到 1 周（纯跑批）。

## 优先级建议

| 顺序 | 方向 | 性价比 | 理由 |
|---|---|---|---|
| 1 | 自适应攻击 | 最高 | 学界最缺、几乎必有发现、简历故事最硬 |
| 2 | 误报基线基准 | 高 | 工作量最小，能立刻把种子 #1 成文 |
| 3 | 跨模型迁移 | 中 | 补短板，但更像「必须做」而非「亮点」 |
